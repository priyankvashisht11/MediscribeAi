───────────────────────────────────────────────────────────────────
SPRINT GOAL
───────────────────────────────────────────────────────────────────
Transform MediScribe from a shared-PIN terminal into a multi-doctor,
clinic-aware product that can be handed to a real clinic without
privacy concerns. The goal is the minimum necessary to be safe for
a pilot with 2–5 doctors sharing a clinic.

By end of Sprint 10:
  - Every doctor has their own email + password login
  - Sessions and patient records are scoped to the doctor's clinic
  - A new clinic can onboard itself in under 5 minutes (solo or team)
  - The PIN gate is replaced — existing PIN falls back gracefully

This sprint DOES NOT include:
  - Public landing page / self-serve acquisition (Sprint 11)
  - Hospital roles (resident / senior / department) — build when asked
  - Billing / subscription management
  - ABHA validation
  - Forgot password email flow (needs SMTP config — Sprint 11)

S10-1 | AUTH SYSTEM — Email/Password Login + JWT Claims (Backend)
──────────────────────────────────────────────────────────────────
BCRYPT PATTERN — use this exactly:

  from passlib.context import CryptContext
  pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

  # Hash a password:   pwd_context.hash(plain_password)
  # Verify a password: pwd_context.verify(plain_password, hashed_password)

  bcrypt rounds = 12 (CryptContext default for bcrypt). This gives ~250ms
  on Fly.io shared-cpu-1x — acceptable for a login endpoint.
  Do NOT use bcrypt directly and manage salt manually.
  Do NOT use sha256, md5, or any non-adaptive hash for passwords.

SECRET_KEY — FAIL HARD IF UNSET:
  Current config.py has: secret_key: str = "change_me_in_production"
  This means if SECRET_KEY is never set on Fly.io, all tokens are signed
  with a publicly known string. Any attacker who reads this file can forge
  admin tokens.

  Fix in config.py:
    secret_key: str = ""

  Fix in auth.py, _make_doctor_token():
    if not settings.secret_key:
        raise RuntimeError(
            "SECRET_KEY is not set. "
            "Run: flyctl secrets set SECRET_KEY=$(openssl rand -hex 32)"
        )

  This means: if SECRET_KEY is missing, no tokens can be issued and any
  attempt to log in returns 500. The server remains up, health checks pass,
  but auth is blocked. This is intentional — better to be obviously broken
  than silently insecure.

  Deploy procedure for new installations:
    flyctl secrets set SECRET_KEY=$(openssl rand -hex 32) --app mediscribe-api
  (Generate a fresh random key — do not copy from any source)

New Pydantic model: LoginRequest
  - email: str
  - password: str

New endpoint: POST /api/auth/login
  1. Normalize email: email.lower().strip()
  2. Fetch doctor by LOWER(email) = normalized_email
  3. If not found → 401 "Invalid credentials"
     (same message as wrong password — prevents user enumeration)
  4. If hashed_password is null → 401 "Account not set up — contact your clinic admin"
  5. If not is_active → 403 "Account disabled — contact your clinic admin"
  6. pwd_context.verify(password, hashed_password) — if fail → 401 "Invalid credentials"
  7. Issue JWT with claims:
       sub: str(doctor.id)
       doctor_id: str(doctor.id)
       clinic_id: str(doctor.clinic_id) if doctor.clinic_id else None
       role: doctor.role
       exp: now + 24h

New endpoint: GET /api/auth/me
  - Requires valid JWT
  - Implementation steps (in order):
    1. Decode doctor_id from JWT sub claim
    2. Fetch doctor by id from DB
    3. If doctor not found (deleted after token issued) → 404 "Doctor not found"
    4. If doctor.is_active is False → 403 "Account disabled — contact your clinic admin"
    5. Fetch clinic name via doctor.clinic_id JOIN
    6. Return: { id, name, specialty, email, role, clinic_id, clinic_name }

  FAILURE HANDLING SPEC (frontend must implement all of these):
    401 / 403 → clear token from localStorage, redirect to /login,
                show toast "Session expired — please log in again"
    404 (doctor deleted) → clear token, redirect to /login,
                           show toast "Account not found — contact your admin"
    Network error / timeout → do NOT redirect to /login
      Show "Connecting…" spinner for up to 10 seconds
      If still failing after 10s: show "Can't reach server — check your
      connection" with a [Retry] button
      The distinction between "logged out" and "offline" must be preserved —
      a doctor on a spotty clinic WiFi should not be randomly logged out

New endpoint: POST /api/auth/register (invite-based only)
  - No JWT required (pre-auth endpoint)
  - Body: { invite_code, name, specialty, email, password, confirm_password }
  - Validation:
      - invite_code must exist, not used, not expired → 410 Gone if expired/used
        (use 410, not 401 — clearer UX: "This invite link has expired, ask your
         admin for a new one" vs "Unauthorized" which implies wrong credentials)
      - email must be unique across all doctors
      - password must match confirm_password
      - password: min 8 chars, at least one letter, at least one digit
  - Creates: Doctor row with clinic_id from the invite, role="doctor"
  - Marks invite as used (used=true, used_by=new doctor id)
  - Returns: JWT (new doctor logged in immediately after registration)

New endpoint: POST /api/auth/setup-password
  - For seeded/invited doctors whose hashed_password is null
  - Body: { setup_token, new_password }
  - setup_token: short-lived (1hr) JWT containing doctor_id in claims
  - Validates new_password requirements
  - Sets hashed_password on the doctor row

  NOTE: Sprint 10 does NOT need a full email delivery system to generate
  setup_tokens. For the pilot, the admin can generate a setup link from the
  /clinic console and share it via WhatsApp. The setup_token is a short JWT
  signed with SECRET_KEY containing { doctor_id, purpose: "setup", exp: 1hr }.

Update _make_token() → _make_doctor_token(doctor: Doctor) → str
  Replace hardcoded sub/doctor_id/null with real values.
  Keep the old _make_token() for PIN fallback only, renamed to _make_pin_token().

Update verify_token() → decode_token(token: str) → dict | None
  Return the full decoded payload dict so routes can read doctor_id + role.
  Return None (not False, not raise) on any decode failure.
  Callers check `if claims is None`.

Update require_auth dependency in main.py:
  Extract doctor_id and clinic_id from JWT claims.
  Attach to request.state:
    request.state.doctor_id: UUID | None
    request.state.clinic_id: UUID | None
    request.state.role: str | None  ("admin" | "doctor" | None for PIN tokens)

PASSWORD VALIDATION RULE:
  Apply at registration and setup-password endpoints only.
  Do NOT reject weak passwords at login — the user might have set their
  password before requirements were introduced.
  Min 8 characters, at least one ASCII letter [a-zA-Z], at least one digit [0-9].

S10-2 | CLINIC CREATION + INVITE FLOW (Backend)
────────────────────────────────────────────────
RATE LIMITING on POST /api/clinics/ (required — do not skip):

  This endpoint has no auth and creates DB rows. Without rate limiting,
  a script can exhaust Supabase free tier in minutes.

  Implement a simple in-memory rate limiter (sufficient for POC):

    from collections import defaultdict
    from datetime import datetime, timedelta

    _signup_attempts: dict[str, list[datetime]] = defaultdict(list)

    def _check_signup_rate(ip: str) -> None:
        now = datetime.utcnow()
        window_start = now - timedelta(minutes=10)
        _signup_attempts[ip] = [t for t in _signup_attempts[ip] if t > window_start]
        if len(_signup_attempts[ip]) >= 3:
            raise HTTPException(
                status_code=429,
                detail="Too many signup attempts. Please wait 10 minutes."
            )
        _signup_attempts[ip].append(now)

  Call _check_signup_rate(request.client.host) at the start of
  POST /api/clinics/ before any DB operations.

  Get the client IP via FastAPI's Request object:
    from fastapi import Request
    async def create_clinic(body: CreateClinicRequest, request: Request, ...):
        _check_signup_rate(request.client.host)

  NOTE: In-memory state is per-process and resets on deploy. This is
  intentional — it's a friction layer, not a security guarantee. For Sprint 11
  when public signups open, move to Redis-backed rate limiting.

New endpoint: POST /api/clinics/ (no auth required — this IS signup)
  Rate limited (see above).
  Body: CreateClinicRequest
    - clinic_name: str
    - plan_type: Literal["solo", "clinic"]
    - admin_name: str
    - admin_specialty: str
    - admin_email: str
    - admin_password: str
  Validation:
    - admin_email unique across doctors
    - password requirements (same rule as S10-1)
    - clinic_name: 2–100 chars
  Creates:
    1. Clinic row (id, name, plan_type)
    2. Doctor row (name, specialty, email, hashed_password, role="admin",
       clinic_id=new clinic, is_active=true)
  Returns: JWT (admin is logged in immediately)

  For plan_type="solo": clinic_name auto-set on frontend to
  "Dr. {admin_name}'s Practice" (user can edit). Backend accepts whatever
  string is sent — no special handling needed.

GET /api/clinics/me — Get current clinic details
  Requires auth (any role).
  Returns: { id, name, plan_type, created_at, doctor_count }

GET /api/clinics/me/doctors — List all doctors in clinic
  Requires auth, role=admin only → 403 for non-admin.
  Returns: [ { id, name, specialty, email, role, is_active, created_at } ]

POST /api/clinics/me/invites — Generate invite code
  Requires auth, role=admin.
  Body: { email_hint?: str }
  Logic:
    - Generate: ''.join(random.choices(string.ascii_uppercase + string.digits, k=8))
    - Insert into clinic_invites (expires_at = now + 48hr)
    - Returns: { invite_code, expires_at, invite_url }
    - invite_url = f"{settings.frontend_url}/join?code={invite_code}"
      (add frontend_url: str = "https://mediscribe-ai-eight.vercel.app" to config.py)

PATCH /api/clinics/me — Update clinic name
  Requires auth, role=admin → 403 for non-admin.
  Body: { name: str }
  Validates: name 2–100 chars, trimmed
  Updates clinic.name in DB.
  Returns: { id, name, plan_type, created_at, doctor_count }

DELETE /api/clinics/me/doctors/:doctor_id — Deactivate a doctor
  Requires auth, role=admin.
  Cannot deactivate yourself → 400 "Cannot deactivate your own account"
  Sets is_active=false (soft delete — data preserved for audit purposes)
  Does NOT delete the doctor row or invalidate existing JWTs immediately.
  (JWT TTL is 24h — deactivated doctors' tokens expire naturally.
   For immediate revocation, Sprint 11 can add a token blacklist in Redis.)

S10-3 | DATA SCOPING — clinic_id ENFORCEMENT (Backend)
───────────────────────────────────────────────────────
This is the privacy enforcement layer. Every query that reads or writes
patients, sessions, notes, or analytics must be scoped to clinic_id.

RULE: All routes under /api/sessions/, /api/patients/, /api/notes/,
/api/analytics/ must add:
  .where(Model.clinic_id == request.state.clinic_id)
to every DB query.

Where clinic_id is null (legacy PIN tokens):
  Skip the clinic_id filter entirely.
  Check: if request.state.clinic_id is not None: [add the filter]
  Legacy data is globally visible to PIN holders only.
  This is the backward-compat escape hatch — remove it in Sprint 11
  once all doctors have migrated to email login.

POST /api/sessions/ — Breaking change:
  - doctor_id is now taken from JWT (request.state.doctor_id), NOT from body
  - Remove doctor_id from CreateSessionRequest body
  - Set session.clinic_id = request.state.clinic_id on creation
  - Set patient.clinic_id = request.state.clinic_id on new patient creation
  - Dedup query must also filter by clinic_id:
    .where(func.lower(Patient.name) == name.lower(), Patient.age == age,
           Patient.clinic_id == request.state.clinic_id)
    (Khushi, 22 at Clinic A is distinct from Khushi, 22 at Clinic B)

WEBSOCKET ENDPOINT — MUST be scoped (security gap from original spec):
  The WS endpoint at /ws/{session_id}?token=JWT currently validates the
  token but does NOT check that the session belongs to the same clinic.
  A doctor from Clinic B who guesses a session UUID can listen to Clinic A's
  live session in real time.

  Add to ws.py, after JWT validation and before accepting the WebSocket:

    session = await db.get(Session, session_id)
    if session is None:
        await websocket.close(code=4004)
        return
    token_clinic_id = token_claims.get("clinic_id")
    if token_clinic_id and str(session.clinic_id) != token_clinic_id:
        await websocket.close(code=4003)  # Forbidden
        return

  WebSocket close codes used:
    4003 = Forbidden (wrong clinic)
    4004 = Not found (session doesn't exist)

ANALYTICS SCOPING:
  All analytics queries must filter by clinic_id at the DB level.
  Do NOT leave clinic_id as an optional query param that callers can omit.
  A doctor cannot see another clinic's stats even if they manually craft a request.

2. uiStore.activeDoctorId
   - In authenticated mode: set activeDoctorId = currentDoctor.id on login
     so the X-Doctor-Id header in api.js interceptor keeps working without change
   - The api.js interceptor reads activeDoctorId from uiStore and sends it as
     X-Doctor-Id header — this stays, no change needed in api.js
   - The chip selector in Settings becomes conditional on legacy PIN mode only

   APP LOAD RACE CONDITION — must be handled:
   On reload, the sequence is: token found → app starts rendering → GET /api/auth/me
   fires async. Between start and resolution, activeDoctorId is still null.
   If any component mounts and fires an API call in that window, X-Doctor-Id
   goes out as null and the backend may return wrong data or 400.

   Fix: the app must NOT render AppShell (and therefore must not mount any
   data-fetching components) until GET /api/auth/me has fully resolved AND
   both setCurrentDoctor() and uiStore.setActiveDoctorId(currentDoctor.id)
   have been called. The "Connecting…" splash screen from S10-4 gates this.
   It is not just an error state — it is the loading state for every app load.
   App.jsx bootstrap pseudocode:
     if (checking) return <ConnectingSplash />   // blocks all renders
     if (!authed)  return <LoginPage />
     return <AppShell />                          // only renders after /me resolved

3. PinGate.jsx
   Keep it. Wrap the auth gating in App.jsx:
   ```
   if (_isLegacyToken(token)) → show PinGate
   else if (tokenValid)       → render app
   else                       → show LoginPage
   ```
   Do not delete PinGate.jsx — the demo deployment still uses PIN=1102.

4. AppShell.jsx BOTTOM_TABS (mobile)
   The mobile "Doctors" tab (to: '/doctors') lists all system doctors.
   After Sprint 10, scoped to clinic doctors only (backend handles this).
   No frontend change needed — just verify the Doctors page shows only
   clinic-scoped doctors after S10-3 scoping is applied.

5. Analytics.jsx, Dashboard.jsx, SessionHistory.jsx — CRITICAL
   All three files use useQuery() with a doctor ID pulled from uiStore:
     const selectedDoctorId = useUiStore(s => s.activeDoctorId)
     useQuery(['analytics-overview', selectedDoctorId], ...)

   After Sprint 10, doctor ID comes from doctorStore:
     const currentDoctor = useDoctorStore(s => s.currentDoctor)
     useQuery(['analytics-overview', currentDoctor?.id], ...)

   If Kiro updates the store but not these query keys, the analytics page
   will silently show stale or wrong data. Update all three files explicitly.

   Search the entire frontend codebase for "activeDoctorId" and replace
   each occurrence with the correct doctorStore equivalent. Do not leave
   any uiStore.activeDoctorId references in data-fetching code.

S10-7 | SECURITY REVIEW CHECKLIST
────────────────────────────────────
Complete ALL items before closing the sprint. No partial marks.

□ Passwords are bcrypt-hashed via passlib CryptContext — never stored plaintext,
  never logged, never returned in any API response
□ SECRET_KEY env var set via flyctl secrets, NOT default string:
    flyctl secrets set SECRET_KEY=$(openssl rand -hex 32) --app mediscribe-api
□ SECRET_KEY unset → server issues RuntimeError at token creation, not a
  silently weak token. Test: temporarily unset SECRET_KEY, attempt login →
  must return 500, not issue a JWT
□ POST /api/auth/login returns identical error message for wrong email and
  wrong password (prevents user enumeration). Verify by testing both cases.
□ POST /api/clinics/ called 4 times within 1 minute from same IP → 4th
  call must return 429, not create a fourth clinic
□ GET /api/patients/ with a Clinic B token must NOT return Clinic A patients.
  Test by creating two clinics, getting a token from each, cross-querying.
□ GET /api/sessions/ same cross-clinic isolation test
□ Admin-only endpoints (POST /api/clinics/me/invites, DELETE /api/clinics/me/doctors/:id)
  tested with a non-admin doctor token → must return 403
□ WS /ws/{session_id_from_clinic_A}?token=<clinic_B_token>
  → WebSocket must close with code 4003, not stream any audio
□ GET /api/auth/me with a valid token for a doctor who was deactivated after
  token issuance → must return 403, not 200 with stale data
□ Expired invite code (used or past 48hr TTL) → POST /api/auth/register
  must return 410 Gone, not 401 or 404
□ Password with fewer than 8 chars or no digits → POST /api/auth/register
  must return 422 with a clear message
□ Doctor cannot deactivate themselves → DELETE /api/clinics/me/doctors/{own_id}
  must return 400
□ PATCH /api/clinics/me with a non-admin doctor token → must return 403
